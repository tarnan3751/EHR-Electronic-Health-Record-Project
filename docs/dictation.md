# Dictation

## Dictation models

Only dictation work needs these; everything else runs without them. They run on the on-prem server only, with no cloud AI.

| Model | Job | Source | Size | License |
|---|---|---|---|---|
| K2 Horizon 7B, Q4_K_M GGUF | Turns a transcript into proposed note fields, in `llama-server` | [IFM/K2-Horizon-7B-GGUF](https://huggingface.co/IFM/K2-Horizon-7B-GGUF) (llama.cpp calls it `IFM/K2-Horizon-7B-GGUF:Q4_K_M`) | About 5.6 GB | Apache 2.0 |
| MedASR | Speech to text, in a Python sidecar | [google/medasr](https://huggingface.co/google/medasr) | Small (105M parameters) | Health AI Developer Foundations terms; gated |
| ECAPA-TDNN speaker embeddings | Tells the voices of a recorded visit apart (listening to a visit), in the sidecar, run by its own port of the network (`ehr_dictation/ecapa.py`); optional | [speechbrain/spkrec-ecapa-voxceleb](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb), pinned to commit `0f99f2d0ebe8` | About 83 MB | Apache 2.0, by its card; not gated. Trained on VoxCeleb, whose other publishers license their weights CC BY 4.0 |
| Whisper large-v3-turbo | Speech to text for dictation in Spanish (the plan's step 17), in the same sidecar; optional | [openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) at commit `41f01f3fe87f28c78e2fbf8b568835947dd65ed9` | About 1.62 GB (809M parameters) | MIT; not gated |

Once: create a Hugging Face account, accept the MedASR terms on its page, create a read-only access token, and sign in with `uvx --from huggingface_hub hf auth login`. The token stays in your user profile, never in the repository. Then, from the repository folder:

```
uv run src/Ehr.Dictation/setup_models.py --dry-run   # what it will download, and how big
uv run src/Ehr.Dictation/setup_models.py             # K2 Horizon, MedASR and the speaker model
uv run src/Ehr.Dictation/setup_models.py --only speaker   # one of them: llm, medasr or speaker
uv run src/Ehr.Dictation/setup_models.py --only whisper   # Whisper, for dictation in Spanish; no sign-in while it isn't gated
```

- K2 Horizon goes in `infra/compose/models/`, MedASR in `infra/compose/models/medasr/`, the speaker model in `infra/compose/models/speaker/`, and Whisper, when asked for, in `infra/compose/models/whisper/`, at the commit the script pins. Without Whisper the sidecar starts and refuses a dictation in Spanish; with it, the sidecar hashes its weights at startup and refuses to start if they aren't the ones the manifest records, as for MedASR. The folder is gitignored, and the script refuses one that Git would track: weights are never committed.
- The speaker model is pinned to a commit, with its weights' size and SHA-256 as they were when it was chosen. Each run asks Hugging Face again, and downloads nothing if it is now gated, its card's licence isn't Apache 2.0, or its weights differ: then the project owner decides again. It needs no account. Without it, or when the port can't load the file the manifest records, dictation works and listening to a visit is refused.
- Every file is checked against the SHA-256 Hugging Face publishes. A second run downloads nothing unless a file is missing or different, and an interrupted run can be restarted.
- `infra/compose/models/models-manifest.json` records the repository, commit, file and SHA-256 of what was installed, for the provenance each dictated note stores. `--verify` re-checks the files against it, offline.
- If you already have the K2 Horizon file (for example from `llama-server -hf`), pass it with `--from-file <path>`. It's used only if it's byte-for-byte the published file.
- The K2 Horizon license and model card are saved in `infra/compose/models/notices/`. Apache 2.0 asks that they go along with the file.
- The dictation sidecar doesn't use MedASR's optional 6-gram language model (`lm_6.kenlm` and `lm_6.arpa.xz`, about 945 MB together). Add `--medasr-exclude 'lm_6.*'` to leave it out.

To run K2 Horizon in the local stack, set `LLAMA_MODEL_FILE` (the script prints the value) and `LLAMA_API_KEY` in `infra/compose/.env`, then start the `ai` profile (see [infra/compose/README.md](../infra/compose/README.md#ai-profile)). K2 Horizon "thinks" before it answers, at length whichever effort its template is given (high, medium or low: at low, over 1,000 tokens and 80 seconds for a two-minute dictation on an M5's GPU), so the `llama` service turns reasoning off (`--reasoning off`), as the sidecar asks on every request. Off, a two-minute dictation takes about 30 seconds there.

K2 Horizon "7B" stores about 9 billion parameters. With an 8K context it needs about 6 to 7 GB of memory, so a computer with 8 GB of RAM struggles. MedASR is small enough for any machine's CPU. Whisper takes about 3.3 GB more in fp32 on a CPU (about half that in fp16 on a GPU); with it and the speaker model loaded, under two visits and six Spanish dictations at once, the `dictation` container peaked at 7.28 GiB, page cache included, which is why its memory cap is 10 GB (the peak plus 25%, rounded up).

## How it works

A clinician dictates, and MedASR transcribes as they speak. When they stop, K2 Horizon sorts the transcript into Subjective, Objective, Assessment and Plan, and every proposed value is checked against the transcript before anyone can see it. What passes is pending until a clinician approves it; nothing is stored. A clinician may choose, for each dictation, to dictate in Spanish (the plan's step 17): Whisper transcribes it, K2 Horizon proposes the fields in English sentence by sentence, each with the Spanish it was translated from, and the sidecar checks each sentence against that Spanish.

- **Listening to a visit** (UC 23), off unless `Ehr:Ambient:Enabled` is true (it is in the local stack). The last run (2026-11-24, on the developer Mac, not the server, the eval's 22 synthetic recordings; `docs/UC23.md` has the rest): field F1 0.3155, 0.3558 as the run first scored it, before the fix round's checks refused the values that offered seven questions as findings and cut an order from a Plan, listing it; 0.5882 of the words labelled with the right speaker and 0.349 Unsure, 65 of 22,225 labelled another speaker's with confidence, in 18 passages; two clean visits more than half Unsure (c06 0.6328, c12 0.5006); the patient's clean word error rate 0.0752; parts drafted in 25.18 seconds on average and 55.25 at most, the longest visit in 199.2. "No order shown" and "no question offered as a finding" are true of that run's drafts only: the checks find an order or a question only in the forms they read ("i'll get that sent over to the chemistvi", "i'll book you in for an altrasound" and "ill need an injection" get through), speech recognition writes no question mark, and 212 of the scripts' 554 questions are found by none of the rules, counted word by word (`metrics.questions`); the rescore before that run also reached zero, and the run found nine. It goes through the same sidecar, with sessions of its own kind (`ehr_dictation/listening.py`) that no dictation call can reach. Nothing is transcribed while it records. At Stop the recording is decoded once and dropped; the speaker model's embeddings of 1.5-second windows are clustered into as many voices as the clinician said would speak (`diarize.py`); MedASR transcribes the visit a turn at a time; and the clinician names every voice: one clinician, one patient, at most one other, and "unsure" for a voice they can't place. A passage is marked unsure, never given to a voice with confidence, when it has fewer than four words, when its windows sit close to two voices or far from their own voice's centre, when the smoothing or a short turn joining its neighbour moved any of them, when they came from a group too small to be a voice, or when its voice was named "unsure": a short "no" between two of the clinician's questions is unsure, not the clinician's. A voice's turn is one line of the transcript however sure each passage is, so nothing a voice says is cut short where only the doubt changes. K2 Horizon then drafts the note a part of about 450 tokens at a time (`conversation.py`, counted by llama-server's tokenizer), with an answer of 1,100 tokens at most, so each part's answer ends within about a minute; a part that times out or runs out of tokens is drafted once more as two halves before the visit is left undrafted. It drafts only while no dictation is waiting or being sorted: a part being drafted gives way the moment a dictation asks, and is drafted again after it; a visit whose parts wait ten minutes in all is left undrafted, with its transcript, as the service being busy. It uses the conversation prompt (`src/Ehr.Dictation/schema/conversation-prompt.md`) and the same schema, and `validation.py` checks each part with the speaker rules on top of every other: Subjective only from what the patient or someone with them said, and never from a passage in the clinician's voice even where whose it is couldn't be told, Objective, Assessment and Plan only from what the clinician said (a source from anyone else discards the value); every negation and doubt read as people speak, past fillers ("um", "given what you've told me"), a verb of belief and a subject ("I", "we" and "you" among them) to what it is about, so "I think um you have gout", "I don't reckon I've had a fever" and "it's unlikely you've had a stroke" are never offered without their hedge; someone else's belief or word, reported by the patient ("my wife thinks I have sleep apnoea"), kept as a report; a question the checks find, by its grammar or because the next speaker answers it, never a finding's source (not every question is found, as above), and an answer alone ("not really") never a value; each Subjective value marked as the patient's own words, and a source whose speaker couldn't be told, or said by someone else in the room, marked too. Instructions said to the patient are cut and listed beside dictated ones, found as acts, a noun of the prescription, a supply, a test or referral, or the allergy list, with its verb in one clause in either order ("I'll send that to your pharmacy", "I'll pop a form in for some blood tests", "I'll put you down as allergic to penicillin"), or the clinician's own sending of a prescription on, by its frame, whatever the place was heard as ("I'll send it over to the chemist", which speech recognition heard as "the chemistvi"), while care described without one stays in the Plan ("we'll get some bloods today", "I'll refer you to the physio"), and so does a test spoken of only as a possibility; where that line falls needs a clinician's reading (`docs/expansion/PLAN.md`, step 16). The clinician's instructions are listed as not carried over, and so are those said in a passage whose speaker couldn't be told, marked so; a patient's request isn't. A visit proposes nothing for the chart (`Session.proposes` is false for it). A visit is up to 20 minutes and 32 MB, two at once.
- **The sidecar** (`src/Ehr.Dictation/sidecar`, Python) does all of it, on the on-prem server only. ffmpeg decodes whatever the browser recorded, in memory. MedASR transcribes it, cut at pauses, and marks passages too quiet, too noisy or too uncertain to trust, which are left out of what K2 Horizon sorts. llama-server runs K2 Horizon with the note schema (`src/Ehr.Dictation/schema`) as its response format. `validation.py` throws away any value whose words aren't all in its sources in the transcript, in order, and cuts out any instruction to order something or change the allergy list, with any piece of its sentence that says nothing without it, and lists each as not carried over; the rest of the value stays. A value that passes but uses a number, dose, date or drug with another of its kind said just after it and a correction-like word between them, which may be a correction speech recognition misheard ("10 mg no weight 20 mg"), carries a possible-correction warning pointing at that place in the transcript; one sorted from words within five of a passage marked unclear carries a near-unclear-passage warning pointing at that passage; and the only value offered, whether the other three fields were not dictated or discarded by the checks, whose sources cover nine in ten of the transcript's words or more, carries a one-field-holds-dictation warning: the whole dictation, plan and findings alike, went into one section, to be sorted before it is accepted. The review screen must show each warning beside its field. What neither warning catches, the clinician's review of each value against the transcript must: a correction more than about eight words after what it corrects, or with no correction-like word between; a correction of a different kind of item (a dose corrected by a date); the corrected value said first; a retraction with no replacement ("scratch the 10 mg"); and a number misheard with no cue at all. Each retracted value the eval shows without a warning is listed, with why, in `eval/known-limitations.toml`. Of the instructions to order something or change the allergy list, the checks propose, once the transcript is final, each order or allergy to add said in a closed sentence (the expansion plan's step 15): its kind, its place and its warnings, never words, and never anything K2 Horizon wrote. A closed sentence is one in which every word of its sentence is accounted for: a closed lead-in, the verb in one of its plain forms, determiners, an item the reference data names, by its own name or a common name mapped to it there (an orderable for an order, an allergen for an allergy to add), the item's quantities and a closed set of trailers, and nothing else; its items come from `ehr_dictation/catalog.py`, which `generate_catalog.py` writes from `db/reference`, the clinic's common catalog items and the common names in `db/reference/dictation-names.toml` (`validation.py`'s header has the classes word for word). Any other word, anything the reference data doesn't name, an unclear passage, is held back, still listed as not carried over; a short sentence after it, read past line breaks and heading lines, must be accounted for too (a step of the plan, a heading with what follows it, or thanks), a negation, a word of error or a condition in any sentence within reach holds it back, and the sentences around it are otherwise read for closed lists of cues; a proposal can still be wrong, and is the clinician's to dismiss (`validation.proposals()`; a kind of session that must propose nothing sets `Session.proposes` to false). A dictation started in Spanish (`{"spokenLanguage": "es"}`) goes another way from start to end (`ehr_dictation/sessions.py`): Whisper (`whisper_asr.py`) transcribes finished passages only, greedy, with Spanish and transcription forced, and marks a passage it didn't hear as Spanish `other_language` and one whose words look made up `low_confidence`; spoken punctuation is only "punto y aparte", "nuevo párrafo" and "punto y seguido". K2 Horizon answers with the Spanish prompt and schema (`structuring-prompt-es.md`, `note-fields-es.schema.json`) as one list of statements, each its Spanish passages, its field and its English, and `translation.py` checks each statement against the Spanish it cites, discarding the whole field if one fails, as `validation.py` discards an English value; the instructions found by `spanish.py`'s detector and `validation.py`'s (one said in English), and the Spanish of any statement whose English the English rule cut, are listed as not carried over, and nothing is proposed. The result says `"spokenLanguage": "es"`, each field's statements, and Whisper in its provenance. The sidecar has no database access, and its logs carry no audio or text. Its API is in the header of `ehr_dictation/api.py`, and its limits in `ehr_dictation/settings.py`.
- **The on-prem app's API** (`src/Ehr.Web/Api/Dictation`) is for clinicians signed in to the web app, and the cloud app forwards it to the on-prem app, but for listening to a visit (`/api/dictation/sessions/ambient`, `AmbientApi.cs`), which it never forwards. Every call answers within 20 seconds; if K2 Horizon is unavailable or too slow, the transcript comes back as plain text with a note that the fields couldn't be sorted. A dictation can be up to 3 minutes: K2 Horizon repeats each field's sources in its answer, so a genuine 5-minute dictation took 98 to 114 seconds to sort on an M5's GPU, over its 90 seconds, and the test set's 3-minute dictations 74 with reasoning on at low; those were measured with the three fields of before the expansion plan's step 14, while a stray test process kept one of the M5's ten CPU cores busy, and haven't been measured again. With reasoning off, in the eval's run on the four fields, the two 3-minute dictations took 48.9 and 55.3 seconds (49.8 on average in its run on three). A dictation in Spanish can be up to 2 minutes: its answer carries English beside every Spanish passage, about 4 tokens a spoken word, so 3 minutes (about 450 words, 1,900 tokens, 95 seconds on an M5's GPU) would outrun the 90 seconds, where 2 minutes (about 300 words) took about 64 seconds in run A2 (the plan's decision log, step 17, decision 20). The Dictate page asks for the language (`spokenLanguage` with the start of a note's dictation), and the plain start and the desktop app's offline recordings are always English. Every result also lists each instruction the clinician dictated to order something or change the allergy list, which no field carries, so the screen can say what still needs placing in Orders or the allergy list, and the orders and allergies to add among them that the dictation proposes, which staging accepts only as listed instructions of the same kind, each once, at most twenty, from a final transcript. Every kind of answer the sidecar gives it is pinned in `src/Ehr.Dictation/contract`: the sidecar's tests write those files from its own code, and the web tests read each one through the API, so neither side can change shape without a test failing.
- **In the local stack** the sidecar is the `ai` profile's `dictation` service (see [infra/compose/README.md](../infra/compose/README.md#ai-profile)).

## Running the sidecar outside the stack

To use the sidecar with `dotnet run`, start llama-server natively as under [Dictation server hardware](#dictation-server-hardware). Then set `DICTATION_API_KEY` (any long random value), `LLAMA_API_KEY` (llama-server's), `DICTATION_MODELS_DIR=infra/compose/models`, `DICTATION_LLAMA_URL=http://127.0.0.1:8080` and, on a Mac, `DICTATION_DEVICE=mps` in the environment, and from the repository folder run:

```
uv run --project src/Ehr.Dictation/sidecar uvicorn --factory ehr_dictation.api:create_app --host 127.0.0.1 --port 8090
```

and tell the web app where it is, once:

```
dotnet user-secrets set Ehr:Dictation:Url http://127.0.0.1:8090 --project src/Ehr.Web
dotnet user-secrets set Ehr:Dictation:ApiKey <the same DICTATION_API_KEY> --project src/Ehr.Web
```

## The eval

The eval (`eval/`) measures the pipeline on a test set of synthetic dictations (`eval/scripts`), recorded by text-to-speech voices with background noise mixed in (`eval/README.md` says how to make the recordings, and how to record the scripts in your own voice). Some voices stand in for accents; they are synthetic stand-ins, not real regional accents. With the models installed, llama-server running and `LLAMA_API_KEY` set:

```
uv run --project eval python -m ehr_eval.run --llama-url http://127.0.0.1:8080 --device mps
```

It writes `eval/results/latest.json`: word error rate overall and per tag, date and drug-name accuracy, note-field precision, recall and F1 against the rule-following gold (the best answer the checks allow, which the gate compares) and beside it against the clinical gold (what a careful clinician would accept), what the checks passed and discarded and why, the share of offered words the transcript doesn't support, any order or allergy change offered (there must be none), any retracted value offered, with and without a warning (without one, there must be none but those the owner has accepted in `eval/known-limitations.toml`), what each warning catches and how often it flags a right value, how many of the dictated orders and allergy changes were reported as not carried over, what the order-and-allergy rule discarded that was legitimate, what the dictation proposed against each script's gold proposals, the rule-following gold (right, misheard where the item it names wasn't heard word for word, or false; each misheard or false one listed, and there must be none but those the owner has accepted in `eval/known-limitations.toml`, a warning or not), and beside it against the clinical gold for proposals (`eval/clinical-proposals.toml`: every one a clinician would expect proposed, those the closed sentence holds back included), and the time per stage, separately for the two-minute dictations and those at the limit. It is stamped with the models' hashes, the prompt, schema and parameters hash, a pipeline hash (the sidecar's code apart from its checks, the eval's `answers.py`, and both lockfiles: what makes the transcript and the answers), a scoring hash (the checks and the rest of the eval's code), the test set's recordings hash (what each script says, and the voices and noise) and gold hash (the rest of each script, both gold sets included, and the clinical gold for proposals), and the machine. The visits' eval (`uv run --project eval python -m ehr_eval.ambient ...`, see `eval/README.md`, Visits) writes `eval/results/ambient-latest.json` the same way, with the word error rate by speaker, the share of words labelled with the right speaker, and its safety measures, which the gate scores again from the stored answers. CI's gate needs each results file it checks to match the commit: a change to what makes the answers or the recordings means running the eval again, and a change only to the checks, the scoring or the gold means scoring the stored answers again (`uv run --project eval python -m ehr_eval.rescore eval/results/latest.json --out eval/results/latest.json`); either way the new results are committed, and every recording in them must have been sorted. The gate also weighs the trick sentences again (`eval/trick-sentences.toml`, `eval/README.md`), from the checks alone. `--reasoning low256` runs the comparison with K2 Horizon's reasoning on at low, capped at 256 tokens, into `eval/results/compare-low256.json`, which the gate doesn't check. `--set es` runs the Spanish test set (`eval/scripts-es`, its audio made with `generate_audio.py --set es`) into `eval/results/latest-es.json`, which the gate checks beside `latest.json`: the Spanish word error rate, drug and date accuracy, the English fields' F1, every translated sentence compared with the Spanish it cites, no instruction shown, and two recordings dictated in the wrong language; `eval/README.md` ("The Spanish test set") says what it measures and checks. The accepted baseline, `eval/results/baseline.json`, is recorded by the owner on the server machine; after that, the gate also fails any run that scores lower, lacks a metric the baseline has, or comes from another machine.

## Dictation server hardware

K2 Horizon 7B runs in llama.cpp's `llama-server`, pinned to build **b11669** on every machine. Support for K2 Horizon arrived in b11454; older builds fail with `unknown model architecture: 'k2-horizon'`. In the local stack it's the opt-in `ai` profile. MedASR runs in the dictation sidecar, in Docker on the CPU, since the model is small; natively on a Mac it can use the GPU (`DICTATION_DEVICE=mps`). Whisper, for Spanish, runs beside it on the same device, in fp32 on a CPU and fp16 on a GPU; it reads a 30-second window for every passage, so a CPU transcribes Spanish more slowly, finished passages only.

| Server machine | How `llama-server` runs |
|---|---|
| Windows, NVIDIA GPU | In Docker: the `ai` profile plus `infra/compose/compose.nvidia.yaml`, which switches to `server-cuda-b11669`. Docker Desktop passes NVIDIA GPUs through WSL2; keep the NVIDIA driver current. The model file alone is about 5.6 GB, so plan on 8 GB of GPU memory. |
| Windows, AMD GPU | Natively: the b11669 Windows Vulkan build from the llama.cpp GitHub release. Docker Desktop can't use AMD GPUs. |
| Apple Silicon Mac | Natively: the b11669 macOS arm64 build, which uses Metal. Or Podman with krunkit running `server-vulkan-b11669`, which keeps it in a container at roughly 75–80% of native speed. Docker Desktop can't use the Mac's GPU. |
| No usable GPU | In Docker: the `ai` profile as is (`server-b11669`), on CPU. |

- A native `llama-server` sits outside the Compose network, so nothing enforces "no internet egress" for it. Start it with the local model file, never with `-hf` or another flag that downloads one, and keep the same safeguards as the container: listen on `127.0.0.1` only, require an API key, turn off the web UI (`--no-webui`), turn reasoning off (`--reasoning off`), and never use `--tools`, `--log-prompts-dir` or `-v` (they would write what patients say to disk or the log). Keep the context the stack uses, 8192 shared by 2 slots: a dictation at the 3-minute limit fits the 4,096 tokens each request gets. For example:

  ```
  llama-server -m infra/compose/models/<file> --host 127.0.0.1 --port 8080 --api-key-file <file holding the key> --no-webui --no-slots -c 8192 -np 2 --reasoning off
  ```
- Record the dictation eval baseline on the server machine itself. CUDA, Vulkan, Metal and CPU builds can produce slightly different output, even at temperature 0.
