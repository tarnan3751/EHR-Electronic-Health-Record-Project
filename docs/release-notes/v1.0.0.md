SwiftChart is an electronic health record for a small clinic: a clinical web app and a patient portal, a desktop app
that keeps a clinician's charts and drafts offline, and dictation that drafts notes on the clinic's own server. It is a
demonstration: every patient, account and record in it is synthetic.

## What is in this release

**The desktop app**, as unsigned test builds:

- macOS, Apple Silicon: `SwiftChart_1.0.0_aarch64.dmg`
- Windows, x64: `SwiftChart_1.0.0_x64-setup.exe`
- Linux, x86-64: `SwiftChart_1.0.0_amd64.deb` (Debian, Ubuntu) and `SwiftChart_1.0.0_amd64.AppImage`
- `SHA256SUMS.txt`, each installer's SHA-256. In the folder you downloaded to: `sha256sum --check --ignore-missing
  SHA256SUMS.txt` on Linux, `shasum -a 256 --check --ignore-missing SHA256SUMS.txt` on macOS, and on Windows
  `Get-FileHash SwiftChart_1.0.0_x64-setup.exe` in PowerShell, compared with its line

**The four images the server stack runs**, for linux/amd64 and linux/arm64, also tagged `latest`:

```
docker pull ghcr.io/tarnan3751/ehr-web:1.0.0
docker pull ghcr.io/tarnan3751/ehr-dictation:1.0.0
docker pull ghcr.io/tarnan3751/ehr-migrate:1.0.0
docker pull ghcr.io/tarnan3751/ehr-lab:1.0.0
```

- `ehr-web`: the web app, which serves the clinic's on-prem site, the cloud site and the patient portal.
- `ehr-dictation`: the dictation sidecar. No model is in the image; `src/Ehr.Dictation/setup_models.py` downloads them.
- `ehr-migrate`: the migration job, which brings the primary database up to date and exits.
- `ehr-lab`: the simulated lab.

**The source**, as the zip and tar.gz GitHub attaches to every release.

## Before you install the desktop app

- **The installers are unsigned test builds.** Nothing is signed by Apple or Microsoft. macOS blocks the first launch
  until you allow it in System Settings, and Windows warns before the install. Nothing signs the Linux packages either.
  [docs/desktop-install.md](https://github.com/tarnan3751/EHR-Electronic-Health-Record-Project/blob/v1.0.0/docs/desktop-install.md)
  says what each one shows, how to get past it, and how to install on Linux.
- **They talk only to the local demonstration stack**, at `https://ehr.example.com:8443` (the clinic's on-prem site)
  and `https://ehr-remote.example.com:9443` (the cloud site), the addresses built into them. Without that stack running
  on your computer, its certificate trusted and those names in your hosts file, the app opens, says it's offline, and
  can't sign in.
- **All data is synthetic.** Don't enter anything about a real person.
- **The in-app updater gets nothing from this release.** A copy checks for updates only on the servers it talks to, and
  installs one only if it's signed with the updater's key, which is kept off CI; nothing in this release is signed with
  it. A newer version is installed over the old one by hand, the same way as the first time.

## Running the server stack

From a clone of the repository at `v1.0.0`, follow the one-time setup in
[infra/compose/README.md](https://github.com/tarnan3751/EHR-Electronic-Health-Record-Project/blob/v1.0.0/infra/compose/README.md):
the settings file, the certificates with mkcert, and the hosts file. Then, from `infra/compose`:

```
docker compose up -d --build --wait
```

It builds its images from the source (the published images are the same Dockerfiles, built by CI) and serves
https://ehr.example.com:8443, https://ehr-remote.example.com:9443 and https://portal.example.com:9443. Its test accounts
are in the same README. To stop it and delete its data: `docker compose --profile "*" down -v`.

## Known limits

- The hands-on checks of the installed desktop app in a real window, on a Mac and on a Windows PC
  (`docs/expansion/20-hands-on-check.md`), are still owed. What macOS and Windows show for an unsigned app is taken from
  Apple's and Microsoft's documentation.
- The Linux app is built and its tests run in CI, but nobody has run it in a Linux desktop session. Its keyring prompts
  are unverified, and recording a dictation or a visit is expected to fail: WebKitGTK gives a page the microphone only
  when the app allows it, and this build doesn't.
- The Linux app is built on Ubuntu 24.04 and needs a C library as new as its own or Debian 13's (glibc 2.38 or newer):
  older distributions can't run it. The Windows app is for x64 only, and the macOS app for Apple Silicon only.
- The images are published for running the stack's services elsewhere; the local stack itself builds its own.
  Barman's image, for backups, is not published.
